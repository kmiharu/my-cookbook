## 実機で行う順番

1. [TestFlight の手順](RELEASE.md#iphoneでインストールして診断を書き出す) に沿って対象ビルドをインストールする。起動、目的検索、案内画面、サンプルの往復、端末内の診断、共有操作を確認する。設定で大きな文字とダークモードに切り替え、VoiceOver で同じ流れを読む。
2. 日記でカメラとマイクの拒否・許可を試し、撮影、録音、保存、開き直しを行う。写真編集と OCR は再現データ、大きい写真、選択の連続変更を試し、処理時間とメモリを記録する。画像や個人情報は計測用の素材に置き換える。
3. HLS を Wi-Fi と帯域制限・切断時に再生し、最初のフレーム、再バッファ、シーク、再試行、復帰を記録する。AR は対応実機で配置、追跡が制限される場面、中断・復帰、リセット、長時間動作を確認する。離脱後にカメラ・AR・再生が止まることを確認する。
4. 地図は位置拒否と通信断を、Bluetooth は許可拒否、機器なし、接続、切断、再接続を試す。接続側の機器や環境を記録する。
5. ローカル・再現サンプルは保存や再起動、空データ、失敗・再試行、重複操作を各 README の条件で試す。書き込み失敗の実機検証は専用のテスト環境で行い、ユーザーのデータを使わない。
6. 診断を共有する。測定には同じビルドで初回と再試行を含め、サンプルごとの操作数を記録する。メモリは Allocations または Memory Graph、CPU は Time Profiler、継続時の発熱は OS の thermal state と端末環境を参照する。記録の見方は [診断の手順](DIAGNOSTICS.md) を参照する。

記録項目は Git SHA、アプリの版・ビルド、機種と OS、通信条件、データ量、操作回数・継続時間、目標、実測、判定、診断ファイルの所在。Simulator と iPhone の結果を分けて残す。
