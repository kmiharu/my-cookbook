# 周辺の場所を探し、徒歩経路を表示する

## 試せること

場所の見本から1件を選ぶと、東京駅から選んだ地点まで見本の直線を表示します。通信できるときは場所の名前や種類で周辺を検索し、選んだ地点までの実際の徒歩経路、距離、所要時間の目安を表示できます。現在地を許可すると、東京駅の代わりに1回取得した現在地を使えます。

## 読む順序と実装理由

1. [MapSampleView.swift](MapSampleView.swift) の `MapSampleView` は SwiftUI の `Map` に地点と線を重ね、検索・位置取得・選択の操作を `MapSampleModel` に渡します。
2. モデルは `CLLocationManager.requestLocation` の最新のコールバックを1回だけ採用し、要求を止めてから表示を更新します。許可前はユーザーの操作を待ち、許可済みの位置要求には12秒の期限を設定しています。
3. `MKLocalSearch` と `MKDirections` は操作の世代を分け、結果が古ければ破棄します。画面を離れるときとバックグラウンドで、タスクとフレームワーク側の要求を止めます。検索は最初の12件、経路は候補1件まで保持します。

流用時は再現データの地点、初期の地図範囲、期待する位置精度、利用目的の文字列、経路の交通手段を変更します。継続追跡が必要な機能では、取得の頻度と停止条件を別に定義してください。

## 端末・権限・接続範囲

現在地には位置情報サービスと「このAppの使用中」の許可が必要です。拒否や制限時は東京駅を起点に試せます。見本の地点・直線は通信不要ですが、地図の背景タイルと周辺検索・徒歩経路にはAppleの地図サービスへの接続が必要です。アプリ専用の外部アカウントは不要です。通常の検索と経路取得では地名や位置をAppleサービスに送ります。診断には地名・検索語・座標を保存しません。

## 性能条件と検証

- **目標・未測定**。iPhone 17、iOS 27.2.1。屋外、Wi-Fiまたは安定した5G、東京駅周辺の「カフェ」検索10回で先頭12件の表示まで中央値2.5秒以下。約1 kmの徒歩経路10回で描画データ到着まで中央値4秒以下。位置取得は権限取得済みで最大12秒とし、検索や経路の画面離脱後にアプリの明示的要求が残らないことを確認します。
- 診断の `map/load`（検索）、`map/process`（経路）、`map/track`（位置）を参照します。位置は屋外・屋内・正確な位置情報オフを分けます。バックグラウンド中止、ネットワーク切断、権限拒否、検索の再試行を確認します。地図タイル自体の通信は MapKit が管理します。
- **実施済み**。LinuxのSwift構文解析とApple公開APIの宣言確認。**未確認**。iOSビルド、シミュレータの模擬位置、実機の位置取得、経路・性能測定。
