# 画像の文字とコードを読み、書類を書き出す

## 試せること

管理番号・件名・QRコードを描いた見本か、写真ピッカーで選んだ画像から文字とコードを読み取れます。読み取り結果を確認し、見本で抽出した項目を書類に反映します。管理番号と件名を修正し、「テキストを書き出す」から「ファイル」などにUTF-8のテキストを保存できます。画像なしでも手入力と書き出しが可能です。

## 読む順序と実装理由

1. [WorkSampleView.swift](WorkSampleView.swift) の `WorkSampleView` が写真の選択、読み取り、編集、出力の入口です。処理途中で中止を指定でき、前の処理が終了するまで次の画像を取り込みません。
2. `DocumentImage` は写真ピッカーの一時ファイルをサイズ確認して取り込みます。`DocumentRecognizer` は Image I/O が長辺1,600ピクセルに縮小した画像だけを読み取り、日本語と英語の文字、QR・Code 128・EAN-13のコードを順に検出します。
3. 検出結果の反映はユーザーが選択します。管理番号、件名、備考は型と文字数を確認し、`WorkDocument` から標準のファイル書き出しを呼び出します。ファイル保存先のエラーでも入力欄を保持します。

実際の書類へ流用する場合は、`DocumentRecognition.field` の見本用対応規則、検証条件、ファイルの出力形式を置き換えます。バーコードの形式を追加する場合は読み取り対象と誤認識対策を仕様化します。

## 端末・外部依存

見本は端末で描画し、Visionによる読み取りも端末内で実行します。写真ピッカーから個別に選ぶため、フォトライブラリ全体へのアクセスは不要です。iCloudにある写真を写真ピッカーが準備するときは通信が必要になる場合があります。入力は20 MiB以内、縦横各12,000ピクセル、4,800万画素までです。同時に1枚処理し、検出した文字は40行、コードは12件まで保持します。画像、入力内容とコード値をアプリ側の診断へ記録しません。

## 性能条件と検証

- **目標・未測定**。iPhone 17、iOS 27.2.1。端末に保存した12 MP JPEGを、明るい紙の写真と斜め・暗所の写真で各10回読み取ります。ファイル準備完了から文字・コード検出が終わるまで95パーセンタイルで1.5秒以下、処理中の追加メモリピーク60 MiB以下を目標にします。クラウドからの画像転送を含む待ち時間は別に記録します。
- 診断の `work/process` と Instruments の Allocations を参照します。別画面に10回往復して画像が蓄積しないことを確認します。白紙、未対応形式、20 MiB超過、選択キャンセル、読み取り中止、容量不足時の出力失敗を確認します。見本の期待値は管理番号 `LAB-1042`、件名 `Equipment return`、QR `COOKBOOK-2026-01` です。
- **実施済み**。LinuxのSwift構文解析とApple公開APIの宣言確認。**未確認**。iOSでの写真選択、Vision実行、テキスト保存、実機の時間・メモリ測定。

## 公式資料

確認日 2026-11-28。対象はiOS SDK 27.2です。サンプル画像は実行時に自作データから生成し、外部画像を含みません。

- 文字・バーコード認識で使用。 [Apple Vision](https://developer.apple.com/documentation/vision)
- 読み取り用画像のダウンサンプリングで使用。 [Apple Image I/O](https://developer.apple.com/documentation/imageio)
- 選択した写真だけを受け取る入口。 [Apple PhotosPicker](https://developer.apple.com/documentation/photosui/photospicker)
