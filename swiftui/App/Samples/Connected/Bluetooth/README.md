# Bluetooth LE機器を探し、電波強度を読む

## 試せること

再現用データで「見本を探索」し、温度計を選んで接続、電波強度の読み取り、切断まで操作できます。「近くのBLE機器」に切り替えると実際に探索し、選んだ機器への接続を試みます。接続後は RSSI と、機器が提供している場合は製造元を表示します。切断後は機器を再選択するか、再探索して接続できます。

## 読む順序と実装理由

1. [BluetoothSampleView.swift](BluetoothSampleView.swift) の `BluetoothSampleView` でモード、探索、接続状態、読み取りを表示します。`BluetoothSampleModel` は画面とデリゲートの状態をメインアクター上に揃えます。
2. `CBCentralManager` は実機探索の操作時だけ初期化します。探索は1回12秒、最大24台で、自動の重複通知は無効です。接続は一度に1台、15秒までです。接続・切断・読み取りには対象機器の一致を確認します。
3. 接続後の製造元取得はサービス `180A` と特性 `2A29` の読み取りを使います。製造元は8秒、RSSIは6秒で結果が得られない場合の案内を出します。画面離脱、バックグラウンド、モード切り替えで探索と接続を解除します。

実アプリに移すときは対象機器のサービスUUIDで探索を絞り、接続条件、機器固有の特性、再接続方針を定義してください。このサンプルの機器操作は読み取りに限定しています。

## 端末・権限・機器

再現用データはBluetoothの権限や機器が不要です。実接続は iPhone、Bluetoothの許可、近くで広告を出し接続を許可するBLE周辺機器が必要です。1台で接続できるかは機器側の設定にも依存します。製造元表示の確認には Device Information Service の Manufacturer Name String を許可した機器を用います。機器名・機器識別子、RSSI、製造元はアプリの診断に含めません。

## 性能条件と検証

- **目標・未測定**。iPhone 16、iOS 27.2.1、広告間隔1秒以下の試験用BLE機器を1 m以内に1台配置します。10回試し、開始から最初の機器表示まで中央値2秒以下、接続完了まで中央値5秒以下、RSSI応答まで中央値2秒以下を目標にします。20分の探索・接続・切断の繰り返しで画面離脱後にアプリの探索・接続が残らないことを確認します。
- 診断の `bluetooth/ready` は最初の発見まで、`load` は探索終了まで、`track` は接続試行、`process` はRSSI読み取りです。許可拒否、無効化、機器の電源断、距離延長、機器の再起動、タイムアウト、バックグラウンド復帰を別々に確認します。シミュレータでは再現用データの画面確認を行い、実接続は実機で測ります。
- **実施済み**。LinuxのSwift構文解析とApple公開APIの宣言確認。**未確認**。iOSビルド、シミュレータの再現操作、実機BLE接続と性能。
