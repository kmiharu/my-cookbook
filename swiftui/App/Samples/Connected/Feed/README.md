# 記事を読み、ブックマークに保存する

## 試せること

「再現用データ」には日本語の記事が60件あります。記事の詳細を開き、ブックマークに追加すると、記事一覧と独立した保存一覧で確認できます。次の12件を明示的に読み込み、詳細からブックマークを外せます。「Hacker News API」に切り替えると公開記事の見出しとコメント件数を取得し、詳細から掲載サイトを開けます。

## 読む順序と実装理由

1. [FeedSampleView.swift](FeedSampleView.swift) の `FeedSampleView` で取得元、ページ番号、取得状態、ブックマークの表示を追います。
2. 同ファイルの `ArticleFeed` が一度取得した上位IDを固定し、各ページの最大12件を並行取得して元の順位に戻します。更新時に新しいID一覧を取得するので、ページ間で順位が変動しても同じページ送りの中で重複しにくくなります。
3. 通信中は該当操作を中止でき、キャンセルされた要求の結果は世代と試行IDの両方で除外します。取得済みページはセッション内で最大5ページを保持します。最後に取得した記事一覧は容量上限内の1件のJSONとして端末内に保存し、次回の更新中と更新失敗時に表示します。ブックマークは独立したJSON配列を保存します。

他のアプリへ移すときは、`ArticleFeed.fetch` の配信先と応答型、記事の識別子、順序を固定する方法を変更します。ページサイズ、キャッシュ容量と有効期間、保存形式は対象APIの契約とデータ量に合わせます。認証やユーザー別キャッシュが必要なAPIでは、利用者切り替え時のキャッシュ消去を定義してください。

## 接続範囲

再現用データに通信・アカウント・権限は不要です。実接続は Hacker News の公開 HTTPS API を使います。掲載サイトは外部サービスです。取得するのは記事のメタデータで、記事本文は掲載サイトで表示されます。1応答96 KiB、記事リスト60件、永続レスポンス120 KiB、ブックマーク100件を上限としています。アプリ内で記事の画像・認証・コメント・投稿操作は扱いません。

## 性能条件と検証

- **目標・未測定**。iPhone 17、iOS 27.2.1。再現用データを5ページ読み込む操作を20回繰り返し、ページ開始から一覧更新まで95パーセンタイルが100 ms以下。Wi-Fiの実接続は冷キャッシュで上位IDと初回12件を取得し、50 Mbps、RTT 40 ms程度で95パーセンタイルが3秒以下。上限に達した後に次ページの要求が出ないことを確認します。
- 「診断」の `feed/load` を書き出して取得時間を確認し、Network Link Conditioner の低速と100%損失で更新失敗・中止・再試行を確認します。画面を往復した場合の通信とメモリは Instruments の Network と Allocations で確認します。永続キャッシュは、実接続成功後にアプリを再起動してオフラインで同じ取得元を選ぶと確認できます。
- **実施済み**。Linuxから公式APIの上位IDと先頭1件のHTTPS応答を確認しました。Swift 6の分離検証では、再現記事60件の重複がなく最終ページで終了し、Linuxの通信アダプター経由で取得した実データ2ページにもIDの重複がありませんでした。**未確認**。iOSビルド、シミュレータと実機での画面操作、iOSのストリーミング読み込みと通信条件別の測定。
